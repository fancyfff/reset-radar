

# 产品设计文档：AI额度重置雷达（Reset Radar）— 最终版

## 一、产品概述

### 1.1 产品定位
**AI额度重置雷达**是一个面向AI开发者的情报聚合与预测工具。通过整合官方公告、服务状态、历史周期、社区反馈、关键人物发言等多维度信息，预测各AI编码平台的**下一次额度重置时间**。

### 1.2 核心价值
- **核心预测**：给出每个平台下一次重置的概率和时间窗口
- **原因追溯**：记录每次重置的原因（如“庆祝活跃用户达1500万”），建立信任
- **信号监控**：追踪关键人物的社交发言，提供早期预警
- **历史回溯**：完整展示历史重置记录，标注“额外重置”

### 1.3 目标用户
海外AI开发者、AI工具重度使用者，技术敏锐，移动端优先。

### 1.4 参考产品
**重置雷达**微信小程序。本产品复刻其核心功能，并加以优化。


## 二、分析维度（完整版）

小程序的分析逻辑包含以下维度：

| 维度                 | 说明                             | 数据来源               | 优先级 |
| -------------------- | -------------------------------- | ---------------------- | ------ |
| **自然周期候选点**   | 基于历史重置记录计算平均间隔     | 历史重置记录           | P0     |
| **历史24小时底座**   | 统计24小时内发生重置的概率       | 历史重置记录的时间分布 | P0     |
| **官方公告**         | 监控额度相关政策变更             | 官方X/博客/状态页      | P0     |
| **模型发布信号**     | 新版本发布作为辅助信号           | GitHub Release         | P0     |
| **社区反馈**         | 用户报告额度恢复的反馈           | X/Reddit/用户提交      | P1     |
| **时段先验**         | 某些时间段重置概率更高           | 历史记录的时间分布     | P1     |
| **事件影响分类**     | 判断事件与重置的关联性           | 规则引擎               | P0     |
| **重置原因标注**     | **新增**：记录每次重置的原因     | 手动录入               | P0     |
| **额外重置标记**     | **新增**：区分常规重置与额外重置 | 手动录入               | P0     |
| **关键人物发言雷达** | **新增**：追踪官方人员社交动态   | X账号监控              | P1     |

### 2.1 事件影响分类规则（核心！）

**上调概率的事件（+权重）**：
- 关键词：`重置`、`恢复额度`、`额度已恢复`、`quota reset`、`limit reset`
- 来源：官方公告、社区反馈

**下调概率的事件（-权重）**：
- 关键词：`限额延长`、`限额提高`、`延期`、`extension`、`increase limit`
- 来源：官方公告

**不影响概率的事件（0权重）**：
- 关键词：`性能下降`、`服务异常`、`已恢复`（仅限服务故障）
- 来源：官方状态页
- 逻辑：服务故障恢复 ≠ 额度重置

### 2.2 重置类型分类（新增！）

| 重置类型     | 说明                         | 对周期计算的影响                 |
| ------------ | ---------------------------- | -------------------------------- |
| **常规重置** | 按自然周期发生的重置         | 纳入平均周期计算                 |
| **额外重置** | 里程碑、庆祝活动等非周期重置 | 不计入平均周期，但单独记录和展示 |
| **未重置**   | 候选时间点未发生重置         | 记录为“不重置”事件               |

## 五、预测算法

### 5.1 核心逻辑：规则引擎

**第一步：计算自然周期候选点**

```
avg_cycle = mean(最近10个常规重置的间隔)   // 即最近11个常规重置点，额外重置剔除
time_since_last = now - last_reset_time
prediction_time = last_reset_time + avg_cycle
```

**第二步：计算周期基线（历史底座）**

```
base = clamp(time_since_last / avg_cycle, 0, 1) * 70%
base_probability = base * 100
```

周期越接近预测点，基线越高（上限 70%）。这是对「未来 24 小时重置概率」的连续估算，取代旧版按 24 小时窗口统计的离散比例（重置样本少时不稳定）。

**第三步：扫描信号事件进行分类加权**

| 信号类型         | 触发关键词                    | 调整 |
| ---------------- | ----------------------------- | ---- |
| 限额延长（官方） | `extension`、`increase limit` | -20% |
| 限额重置（官方） | `quota reset`、`limit reset`  | +30% |
| 模型发布         | `release`、`CLI`              | +10% |
| 服务故障恢复     | `incident`、`degraded`        | 0%   |
| 里程碑临近       | 用户量接近整数关口            | +10% |

**第四步：输出最终概率**

```
final_probability = clamp(base_probability + sum(adjustments), 0, 100)
```

### 5.2 重置类型判断（引擎自动判定）

| 条件                                            | 标记为                     |
| ----------------------------------------------- | -------------------------- |
| 重置原因包含“庆祝”/“里程碑”/“milestone”/“达到”/“突破” | 额外重置（不计入周期）     |
| 重置落在前一条常规重置的预测点 ±2小时窗口内     | 常规重置                   |
| 常规重置的预测点已过窗口(±2h)且无任何记录       | 不重置（`no_reset`，自动追加 `source:"auto"`） |

判定由 `update.py` 在每次运行时自动完成：原因含里程碑关键词即标记为额外重置；每条常规重置的下一预测点若已超过「预测点+2小时」且该时间点无记录，则自动追加一条「不重置」记录（仅用于展示与历史回溯，不参与周期计算）。实测重置记录仍可人工/脚本补充（见 `scripts/record_reset.py`）。

### 5.3 精确倒计时

```
seconds_until_prediction = prediction_time - now
display = 将秒数转换为“X天X小时X分钟”格式
```

### 5.4 发言雷达逻辑

- 每30分钟检查指定X账号的最新推文（可选 X API 实时抓取，默认离线种子）
- 统计今日发言数量
- 检测发言内容是否包含关键词：`quota`、`limit`、`reset`、`extension`、`额度`、`限制`、`限额`、`codex`、`重置`
- 包含关键词的发言在列表中以特殊标记高亮（并记录命中词 `keywords`）

### 8.4 发言雷达实现

```python
# speaker_monitor.py 核心逻辑（默认离线种子，可选 X API 实时抓取）
KEYWORDS = ["quota", "limit", "reset", "extension", "额度", "限制", "限额", "codex", "重置"]

def build_speakers(now):
    for sp in config.SPEAKERS:
        # 配置 X_API_BEARER 后实时抓取最近推文（X API v2），否则用种子
        posts = fetch_x_posts(sp["handle"], limit=20) if X_API_BEARER else []
        posts = posts or sp["seed_posts"]

        for t in posts:
            t["has_keywords"], t["keywords"] = contains_keywords(t["content"], KEYWORDS)

        today = [p for p in posts if is_today(p["time"], now)]
        return {
            "is_active": len(today) > 0,
            "post_count_today": len(today),
            "recent_posts": posts[:10],
        }
```

> 说明：X 官方 API 需付费 Bearer Token，未配置时默认使用 `config.SPEAKERS` 中的 `seed_posts` 离线种子驱动页面，避免引入付费依赖。
